# ATS SCAN — MATCH ANALYSIS

Whenever I provide a job description, **always begin with an ATS match analysis before suggesting any changes**.

The purpose is to determine how well my current master resume matches the specific job.

## LANGUAGE RULE

The language of the job description determines the language used for all suggestions and tailored content.

* If the job description is written in **English**, make all suggestions, recommendations, and LaTeX replacement wording in **English**.
* If the job description is written in **Norwegian**, make all suggestions, recommendations, and LaTeX replacement wording in **Norwegian**.
* Do not switch languages based on the language of the master resume; use the job description's language for the tailored suggestions.
* Unchanged resume content may remain in its original language when it is shown for reference.

---

## MATCH TABLE

Create a table containing the important requirements, skills, and keywords from the job description.

Use these three match levels:

🟢 **STRONG MATCH** — My resume clearly demonstrates this requirement or skill.

🟡 **PARTIAL MATCH** — My resume contains related experience, but the connection could be made clearer or the terminology could be improved.

🔴 **NO MATCH** — There is no evidence in my master resume that I have this experience or qualification.

Use the following format:

| Requirement / Keyword    | Match            | Evidence / Explanation                                                               |
| ------------------------ | ---------------- | ------------------------------------------------------------------------------------ |
| AWS                      | 🟢 Strong Match  | AWS SecurityHub and GuardDuty experience                                             |
| Vulnerability Management | 🟡 Partial Match | Related security testing experience, but the exact terminology is not currently used |
| CISSP                    | 🔴 No Match      | No CISSP certification in the master resume                                          |

The table should appear **near the beginning of the analysis**, before detailed recommendations.

---

## MATCH RULES

Be strict when determining matches.

### 🟢 STRONG MATCH

Use this when the master resume clearly demonstrates the requirement.

Examples:

* The job asks for AWS and my resume explicitly contains AWS experience.
* The job asks for Terraform and my resume explicitly contains Terraform.
* The job asks for cybersecurity education and my resume contains my Bachelor's degree in Digital Infrastructure and Cybersecurity.

### 🟡 PARTIAL MATCH

Use this when there is genuinely related experience, but:

* Different terminology is used.
* The experience is broader or narrower than the requirement.
* The connection is not obvious from the current wording.
* Academic/project experience is relevant but does not fully satisfy a professional-experience requirement.

A partial match may be a candidate for rewording.

### 🔴 NO MATCH

Use this when the master resume does not provide evidence for the requirement.

Do NOT attempt to turn a red requirement into a green or yellow match simply by rewriting the resume.

Do NOT add the missing qualification.

# SKILLS SECTION — HARD LIMITS

The resume has a **hard maximum of 20 skills in total**.

This means the combined number of skills in:

* `Ferdigheter`
* `NTNU`

must never exceed **20 skills altogether**.

The distribution does not need to be equal. For example:

* 15 Ferdigheter + 5 NTNU = 20
* 10 Ferdigheter + 10 NTNU = 20
* 12 Ferdigheter + 8 NTNU = 20
* 10 Ferdigheter + 3 NTNU = 13

Choose the distribution based on what is most relevant to the job.

**Never exceed 20 skills total.**

## SKILL SELECTION

When tailoring the resume, prioritize skills based on:
